# Code standards

Formatting is Prettier, linting is ESLint, and both are non-negotiable — a commit
cannot bypass them, because `husky` + `lint-staged` reformat staged files on every
`git commit`.

**Before ending a coding session, run `npm run check`.** It must exit 0. If it
does not, fix the underlying code rather than suppressing the report — reach for
`eslint-disable`, `@ts-expect-error`, or `any` only with a stated reason.

| Command                           | What it does                                                                               |
| --------------------------------- | ------------------------------------------------------------------------------------------ |
| `npm run check`                   | Verify formatting, lint, and types. Changes nothing. **Run this at the end of a session.** |
| `npm run fix`                     | Apply Prettier and ESLint autofixes in place.                                              |
| `npm run check:all`               | `fix`, then lint, typecheck, and a production build. Run before deploying.                 |
| `npm run format` / `format:check` | Prettier alone, writing / verifying.                                                       |
| `npm run lint` / `lint:fix`       | ESLint alone, reporting / autofixing.                                                      |
| `npm run typecheck`               | `tsc --noEmit`.                                                                            |

The `/check` slash command runs the fix-then-verify pass and repairs whatever fails.

`convex/_generated/` is generated by `npx convex dev` and `.agents/skills/` is
vendored third-party content; both are excluded from linting and formatting. Do
not hand-edit either.

# Agent skills

Skills live in `.agents/skills/` and are committed. `.claude/skills/` is a
per-tool mirror that is **not** committed — after a fresh clone, restore it with:

```
npx skills experimental_install
```
